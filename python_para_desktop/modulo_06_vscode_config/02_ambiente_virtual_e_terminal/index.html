    02. Ambientes Virtuais (venv) e Terminal Integrado¶

    Curso: Python para Desktop
    Módulo: 00 — Configuração do VS Code & Ambiente Python
    Nível: Intermediário Didático
    Tempo estimado: 20 min

    🎯 Objetivos de Aprendizagem¶

    Ao final deste capítulo, você será capaz de:

    • Entender a importância de usar Ambientes Virtuais (venv) em cada projeto.
    • Criar e ativar um venv no terminal do VS Code.
    • Resolver o erro comum de Política de Execução de Scripts no Windows PowerShell.
    • Selecionar o Interpretador Python correto no VS Code.
    • Instalar bibliotecas externas com pip de forma isolada e segura.

    💡 O que é um Ambiente Virtual (venv)?¶

    Imagine que o Projeto A precisa da biblioteca CustomTkinter versão 5.0, e o Projeto B precisa da versão 4.0. Se você instalar tudo no Python global do sistema, um projeto vai quebrar o outro!

    A Metáfora da Maleta Isolada

    Um Ambiente Virtual (venv) é como uma maleta de ferramentas exclusiva para aquele projeto. Tudo o que você instala com pip dentro da maleta fica isolado e não afeta o resto do computador.

    🛠️ Criando o Ambiente Virtual Passo a Passo¶

    No terminal integrado do VS Code (Ctrl + ~), certifique-se de estar na pasta do seu projeto e execute:

    # Criar a pasta 'venv' com o ambiente isolado
python -m venv venv

    Após alguns segundos, uma pasta chamada venv aparecerá no seu explorador de arquivos!

    🚀 Ativando o Ambiente Virtual no Terminal¶

    .\venv\Scripts\Activate.ps1

    source venv/bin/activate

    Quando ativado com sucesso, o terminal exibirá (venv) no início da linha de comando: 

    (venv) PS E:\meu_projeto>

    ⚠️ Erro Clássico no Windows: "A execução de scripts foi desabilitada neste sistema"¶

    Ao tentar ativar o venv no PowerShell do Windows pela primeira vez, você pode receber a seguinte mensagem vermelha:

    .\venv\Scripts\Activate.ps1 : O arquivo não pode ser carregado porque a execução de scripts foi desabilitada neste sistema.

    🔧 Como Resolver em 1 Minuto:¶

    1. Abra o PowerShell do Windows como Administrador (Clique com botão direito no menu Iniciar ➔ PowerShell como Administrador).

    2. Digite o comando: 

      Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

    3. Digite S (Sim) e feche o PowerShell.

    4. Volte ao VS Code e tente ativar o venv novamente!

    🎯 Selecionando o Interpretador Python no VS Code¶

    Para que o VS Code saiba que deve usar a versão do Python que está dentro da pasta venv:

    1. Pressione Ctrl + Shift + P para abrir a Paleta de Comandos.
    2. Digite Python: Select Interpreter.
    3. Selecione a opção que indica o caminho do seu ambiente virtual: .\venv\Scripts\python.exe (ou ./venv/bin/python).

    📦 Instalando Bibliotecas com pip no venv¶

    Com o (venv) ativo no terminal, você pode instalar qualquer biblioteca com total segurança:

    # Atualizar o gerenciador de pacotes pip
python -m pip install --upgrade pip

# Instalar bibliotecas do nosso curso
pip install customtkinter==5.2.2 requests python-dotenv

# Congelar as dependências instaladas no arquivo requirements.txt
pip freeze > requirements.txt

    Exercícios¶

    Básico (fixação)¶

    No terminal integrado do VS Code, dentro da pasta curso_python:

    1. Crie um ambiente virtual chamado venv e ative-o (o nome (venv) deve aparecer no início da linha).
    2. Instale o CustomTkinter na versão do curso: pip install customtkinter==5.2.2.
    3. Liste os pacotes instalados e gere o arquivo requirements.txt.
    4. Desative o ambiente e confira que o (venv) sumiu.
    Gabarito — Básico

    Uma solução possível — compare com a sua. Outras formas também podem estar certas.

    Terminal (PowerShell)
    # 1) Criar e ativar o ambiente virtual
python -m venv venv
.\venv\Scripts\Activate.ps1          # Linux/macOS: source venv/bin/activate

# 2) Instalar o CustomTkinter na versão do curso
pip install customtkinter==5.2.2

# 3) Listar e registrar as dependências
pip list
pip freeze > requirements.txt          # o arquivo lista pacote==versão de tudo que está no venv

# 4) Sair do ambiente
deactivate

    Intermediário (aplicação)¶

    Crie o arquivo estou_no_venv.py que mostre se o programa está rodando dentro ou fora de um ambiente virtual, e qual Python está sendo usado. Rode-o com o venv ativado e desativado e compare.

    Dica: dentro de um venv, sys.prefix (a pasta do ambiente) é diferente de sys.base_prefix (a pasta do Python instalado).

    Gabarito — Intermediário

    Uma solução possível — compare com a sua. Outras formas também podem estar certas.

    # estou_no_venv.py
import sys

if sys.prefix != sys.base_prefix:
    print("✅ Dentro de um ambiente virtual")
    print(f"   Ambiente: {sys.prefix}")
else:
    print("❌ Fora de um ambiente virtual (usando o Python do sistema)")

print(f"Python em uso: {sys.executable}")

    Avançado (desafio)¶

    Crie o conferir_requirements.py, que lê o requirements.txt e, para cada linha pacote==versão, informa se o pacote está instalado na versão certa, em outra versão ou não instalado. Use importlib.metadata.version(nome) para descobrir a versão instalada. Ele é útil quando um colega diz "na minha máquina funciona".

    Gabarito — Avançado

    Uma solução possível — compare com a sua. Outras formas também podem estar certas.

    # conferir_requirements.py
from importlib.metadata import PackageNotFoundError, version
from pathlib import Path

ARQUIVO = Path("requirements.txt")

if not ARQUIVO.exists():
    print("requirements.txt não encontrado nesta pasta.")
else:
    problemas = 0
    for linha in ARQUIVO.read_text(encoding="utf-8").splitlines():
        linha = linha.strip()
        if not linha or linha.startswith("#") or "==" not in linha:
            continue  # ignora linhas vazias, comentários e pacotes sem versão fixa
        nome, esperada = (parte.strip() for parte in linha.split("==", 1))
        try:
            instalada = version(nome)
        except PackageNotFoundError:
            print(f"❌ {nome}: não instalado (esperado {esperada})")
            problemas += 1
            continue
        if instalada == esperada:
            print(f"✅ {nome} {instalada}")
        else:
            print(f"⚠️ {nome}: instalado {instalada}, esperado {esperada}")
            problemas += 1

    print("Tudo certo!" if problemas == 0 else f"{problemas} problema(s) encontrado(s).")
